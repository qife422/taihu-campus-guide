# 无锡太湖学院校园模型

当前状态：技术基线已生成，视觉成品尚未完成。2026-09-08 对照用户案例复审后，地面边界、逐栋辨识度、绿化与水面层次及整体地图呈现仍需精修。下列文件是当前开发基线，不代表最终交付已验收；详见项目进度和 manifest 的 visual_acceptance。

本场景依据两幅 Esri 卫星影像逐栋描绘可见屋顶，接入独立中央样板中的六号教学楼、湖西庭院及湖东北楼群。2026-09-08 已将其余 127 个建筑部分细化为按影像屋顶、照片立面类型和逐栋估计层数生成的全校场景。用户于 2026-09-07 明确授权自主分析与估算高度，并扩展至全校。它是用于导览展示的建筑外观模型，不是测绘、施工或竣工模型。

## 交付文件

- `campus.blend`：可编辑场景，独立建筑编号、材质、正交相机与隐藏的定位参考图。中央三组为可选中的合并网格，独立构件仍可在 `../study/campus.blend` 中编辑。
- `campus.glb`：Draco 压缩的 GLB，保留建筑对象名称与估算属性；播放器需支持 KHR_draco_mesh_compression。35 个无法直接导出的程序材质显式保留 Blender 原有基色；外围影像纹理仍使用原地理 UV。程序纹理在网页上作轻量表现近似。
- `campus.png`：8192×4608 鸟瞰总览；`campus-plan.png`：8192×4096 俯视校核图。
- `campus-detail.png`：3200×2000 北区建筑群近景。
- `layout.json`：逐栋轮廓、层数/层高/高度范围、道路、场地、校门与绿化位置。
- `campus.geojson`：WGS84 建筑、场地及道路数据；含中央样板引用。
- `建筑对应表.md`：每个新增建筑的区域描述与高度取值。
- `validation.json`、`manifest.json`：校验范围与可追溯的内容指纹。
- `alignment.png`：南区、中区、北区及北端的卫星轮廓对照。
- `verify_scene.py`：独立检查建筑 XY 范围、高度范围及相机构图；可重新导出压缩 GLB。

## 范围与估算方法

新增 127 个建筑部分，另复用中央样板 3 组细化建筑；包括南校区、花卉园、中区、北区和北端地块，4 处运动场及可见校内道路。另表达卫星中可见的邻接林地，林地外缘不是学校产权边界。建筑“部分”与官方独立楼栋不是同一统计口径，庭院的不同翼楼可能分别建模。

平面坐标来自影像服务实际返回的 EPSG:3857 范围，不使用旧页面的演示坐标。主影像为 2304×3840，描绘使用半尺寸检查坐标；北端补充影像为 1000×900。中央样板依据自己的独立影像范围转换到同一坐标框架。场景以纬度 31.578° 对 Web Mercator 长度进行局部缩放，单位为米。

高度采用“照片层数判断 × 用途层高 + 屋顶构造”的可编辑估算：宿舍每层取 3.1m，普通教学部分取 3.6m，服务楼部分取 3.8m；这些是本项目建模假设，不是网页提供的实测值。校方航拍可看出北区有低层翼楼、普通多层宿舍及更高的公寓/服务楼，因此逐栋分配 1–8 层，不统一拉伸。新建筑高度范围为建模估计的上下浮动区间，非统计置信区间。中央细节继续沿用其照片估算参数。

北区公寓采用照片支持的浅红色外墙、阳台和深色坡屋顶；红砖庭院教学建筑采用不同的窗组和浅色竖向构架；蓝色、浅色和深色屋顶按各自固定影像取样，少量有照片依据的屋顶单独标注。凹形、庭院形坡屋顶依据原始边界生成坡面；平屋顶增加女儿墙和接缝。窗框、楼层线、浅色构架、坡屋顶与女儿墙以已有照片表现出的建筑语言作类型化解释。无法看到的立面采用简化延续；窗格数量、结构开间、层高、屋顶坡度与栏杆尺寸不是逐项实测。未在卫星中看到的楼栋不按示意图凭空补造。绿色像素仅用于挑选绿化簇位置，树冠形状和树高是示意表达。本场景保留 1855 个全校影像取样树冠，并接入中央样板 119 个树冠位置；全校场景使用共享叶片网格和较低细节树冠，独立中央样板仍保留其高细节树冠。

## 呈现参考与地面处理

用户提供的 [武汉理工大学校园 GIS](https://gis.whut.edu.cn/index.shtml) 是主要呈现参考，另查看了 [上海科技大学官方 2.5D 地图介绍](https://openinfo.shanghaitech.edu.cn/2019/0710/c147a43581/page.psp)。参考其鸟瞰层级、建筑可辨性、清晰道路和绿化关系；其他学校的建筑轮廓没有用于太湖学院建模。

校内保留矢量地面。铺装依据固定影像中的近中性浅色区域提取，经 7 像素闭运算、3 像素开运算、有限边界平滑及面积筛选后，与手工核对的路面、步道合并，并排除楼顶、水体、运动场、草坪和中央样板区域。自动分类仍可能把遮挡或阴影边界解释不完整，不能视作工程铺装图。花园与庭院步道、草坪边界保存在 layout 的 landscape 字段。

校外钱荣路等直接采用固定、带地理范围的影像作为 48 米外围背景，不再使用已发现偏移的旧路面线条。旧线条在 layout/GeoJSON 中保留历史解释状态，标为未验证和未建模，不作为导航数据。

## 校核与已知边界

逐栋简单多边形检查涵盖重复点、自交、非零面积和 GeoJSON 外环方向。此次 127 个建筑轮廓的固定输入指纹与细化前一致；校验器逐顶点比较场景主体坐标，并独立核对中央三组的全部顶点、面结构和逐面材质分配。先在双精度下减去地理原点，再转换到 Blender 局部坐标，避免大坐标提前舍入。这里的数值一致性不代表影像本身具有毫米级实测精度。俯视与卫星对比用于发现位置/朝向问题；这些检查不提供实地精度保证。

- 主体轮廓多数是可见屋顶，尚未校正倾斜位移、屋檐外挑与遮挡，不能称为实测落地轮廓。
- 除六号楼等有明确照片依据的名称外，编号配合“北区公寓”等区域描述；未擅自绑定正式宿舍号或学院名称。
- 校门保留定位节点，未虚构门楼外观；内部结构、室内空间、地下空间不在本外观模型范围内。
- 地形未取得高程数据，因此地面未做测绘式起伏；绿化只表达可见簇的示意树冠。
- 网页三维入口使用本次 GLB，并保留其树冠、铺装与湖岸；不再叠加旧模型的替代几何。默认地图仍为卫星入口。网页模型交互的检查结果单独写入 validation，不代表路线可通行性已验证。

## 复现

在项目根目录运行：

```sh
PYTHONDONTWRITEBYTECODE=1 /opt/anaconda3/bin/python model/campus/prepare.py --export-only
PYTHONDONTWRITEBYTECODE=1 /opt/anaconda3/bin/python model/campus/roads.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python model/campus/build.py
/Applications/Blender.app/Contents/MacOS/Blender --background -t 4 --python model/campus/render.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python model/campus/verify_scene.py
```

追加 `-- --preview` 写 `/tmp/taihu-full/campus.blend` 和 2600×1300 预览；追加 `-- --candidate` 将可编辑文件与 GLB 都写入该临时目录。候选验收使用 `verify_scene.py -- --candidate`，通过后才替换正式文件。已保存的树冠位置不在普通重建时重新采样。

容量预算详见 `../README.md`。不自动删除临时产物或历史文件。建模直接使用 Blender/GIS；网页接入与检查所用 skill 见文末。

8K 图使用 4×4 分块渲染，每块有 32 像素重叠，裁去重叠边缘后原生拼接。render.py 将单块 PNG 交给持久的 Pillow 进程，在内存中完成一幅图后写入正式文件；磁盘只复用 `/tmp/taihu-full/render-tile.png`，不会持续累加分块。旧临时分块保留，但不作为本轮活动证据。鸟瞰 24 采样、俯视 16 采样、近景 32 采样，使用 Cycles 去噪。每块内容指纹、采样与最终输出指纹进入本轮 manifest。

道路显示网格经过屋顶、水面和中央样板边界裁切，最终交叠面积检查见 validation。它们仍是显示几何，不是可通行导航网络。Blender 文件默认预览为 2600×1300、4 线程；8K 输出使用上述有界分块流程。近景复现：`render.py -- --detail`，自动完成拼接。

纯建模部分直接使用 Blender/GIS 脚本；网页接入使用 `redesign-existing-projects` 主 skill 和 `playwright` 验收 skill，未叠加其他近似审美或生图 skill。
